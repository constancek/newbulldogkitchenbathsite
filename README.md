# Bulldog Kitchen & Bath — Website

Static marketing site for **bulldogkitchenbath.com**. Plain HTML/CSS/JS, generated by a small Node script with no dependencies.

## Structure
```
src/
  site.js            # business info, nav, footer links  <- PLACEHOLDERS live here
  components.js      # shared header/footer + section components
  icons.js           # inline SVG icons
  build.js           # every page is defined here
  images.js          # turns new or replaced photos in images/ into WebP
  content/           # product, FAQ and legal copy
  content/blog/      # one Markdown file per blog post (front matter + body; draft: true hides it from the live site)
images/              # every site photo, sorted by page: replace photos here
  blog/              # blog photos, named blog-<post-file-name>
public/              # generated site (deploy this folder)
  assets/css, assets/js
  assets/img/        # converted photos in the same folders as images/, plus brand/ (logo, home-screen icon, badge) and form-icons/
image-credits.json   # Pexels photographer credits for placeholder photos
blog-planning/       # content calendar and customer avatar the blog agent works from
.claude/skills/      # the bulldog-blog-agent skill Claude uses to write posts
.github/workflows/   # build.yml rebuilds public/ and converts photos on every push; notify-discord.yml posts blog PRs to #bath-blog
BLOG-REVIEW.md       # how to review, photograph and publish a blog post on GitHub
```

## Blog
Posts are Markdown files in `src/content/blog/`. Claude drafts them (scheduled task or `/bulldog-blog-agent` in Claude Code) as pull requests with `draft: true`; a reviewer edits, adds photos and flips `draft: false` before merging. See `BLOG-REVIEW.md`. The GitHub Action builds branches with drafts included (so Vercel previews show them) and `main` without, so a draft can't go live. Locally, `INCLUDE_DRAFTS=1 npm run build` includes drafts.

## Build & preview
```
npm run build     # regenerates HTML into public/
npm start         # serves public/ at http://localhost:3000
```
Requires Node 18+. Links are root-relative (`/products/showers/`), so preview through a local server rather than opening files directly.

## Before launch
- Replace placeholders in `src/site.js` (phone, address, email, hours, service area, years in business, social links), then `npm run build`.
- Forms are front-end only (`data-placeholder-form`). Connect them to HubSpot, Formspree, Zapier, etc.
- Replace placeholder photos in `images/` with real project photos (same file name, any of .jpg/.png/.webp), then `npm run build`. See `images/HOW TO REPLACE PHOTOS.txt`. Converting needs ffmpeg installed.
- Review promo/financing copy and the placeholder legal pages (privacy, terms, accessibility, warranty).

## Deploy
Point Netlify, Vercel, Cloudflare Pages, or any static host at the `public/` folder (no build step needed, or use `npm run build`).
